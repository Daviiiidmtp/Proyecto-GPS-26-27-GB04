# Constitución

## Principios
* *Especificación previa:* Toda funcionalidad orientada a la tienda de cartas o gestión de eventos debe estar especificada antes de ser implementada.
* *Calidad y comportamiento verificable:* Los requisitos para el registro de usuarios, compras y torneos tendrán criterios de aceptación claros.
* *Privacidad:* El proyecto utilizará bases de datos ficticias tanto para los productos como para los clientes.

## Development and Documentation Standards
La cadena de trazabilidad será obligatoria: Necesidad → requisito → plan → tareas → código → pruebas[cite: 4].
Los documentos spec.md, plan.md y tasks.md mantendrán responsabilidades separadas[cite: 4].

## Quality Gates and Delivery Workflow
Antes de aprobar código o especificaciones, otro miembro del equipo (distinto al autor) debe validar que se cumple esta constitución, que el alcance es el acordado y que las pruebas están definidas[cite: 4].

## Governance
Cualquier cambio en este documento requiere la decisión explícita del Product Owner, justificación en una reunión y registro de la nueva versión[cite: 4].
